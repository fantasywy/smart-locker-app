### 第 2 轮补到的平台事实（微信官方文档实测，非推断）

- 「扫普通链接二维码打开小程序」官方文档确认：扫码进入时**页面 `onLoad` 拿到 `q` 参数 = 完整链接的 URL 编码**，需 `decodeURIComponent(q)` 一次；**另附 `scancode_time`**（UNIX 秒，用户扫码时间）。出处 developers.weixin.qq.com/miniprogram/introduction/qrcode.html §四。
- **硬前置（须登记为上线依赖，不在本 effort）**：① 开放范围仅「企业 / 媒体 / 政府及其他组织类型小程序」，**个人主体不支持**；② 域名须 **ICP 备案**；③ 校验文件要放在规则 URL 的**最后一级子目录**（`https://<域名>/l/<校验文件>`）；④ 一个小程序账号可配 ≤ **500** 条前缀规则（我们用 1 条 `https://<域名>/l/` 子路径匹配即可）；⑤ **小程序必须先发布线上版本，才能发布二维码跳转规则**。
- 小程序的**当前骨架仍是官方模板**（`pages/index` + `pages/logs`、无 `tabBar`、`navigationStyle: custom`），没有任何历史约束 → 页面骨架由 D1 第 2 轮从零定。

- 401 的重放安全性：401 由鉴权拦截器在业务逻辑之前返回 → 请求**未被执行**，重放写请求（建单/取消/建预约/支付）不构成重复提交；真正「可能已生效但响应丢失」的场景是**网络超时**（非 401），需另走读接口核对而非重放。

- **Q5 = (b) 骨架屏为常态 + (c) 的静态内容作失败出口**，且**失败出口全局只做一次**（由启动态驱动，不下放到每页数据区）；**不做本地数据缓存**（取件码/订单状态属「看到就必须是真的」的数据，缓存说谎比空白更糟；首屏加速靠骨架屏而非数据缓存）。
- **Q6 = (a) 完全透明重放**（含写请求，因 401 下请求未执行）；**重登也失败 → 原动作丢弃、不做后台补发**（否则会出现「用户离开后自动扣款」）；`401+2005` 与冷启动登录失败**共用同一个降级出口**；**同一时刻只允许一次登录失效处理**（并发 401 不得触发多次重登）——此约束交给 D7 请求层实现。
- 登录失败成因穷举：网络不通 / `wx.login` 失败 / `13.1` 返回 `8001` / 后端 5xx。**没有「账号被封不能登录」这一种**（`API设计文档.md:939` 明写「黑名单用户允许登录」）。

### D1 第 3 轮裁决（用户「按推荐」）

- **Q7 = (b)+(a) 拆两类**：**能拿到柜机数据**（含 `online=false`/`status=FAULT|MAINTAINING|OFFLINE`）→ 落地页**完整渲染**柜机信息、把不可用入口**置灰并写明原因**（`§16 #29`④ 后端明说的意图：「小程序选柜页按 `online`/`cellAvailability` 置灰入口」；`online=false` 是**正常响应**不是错误）；**拿不到数据**（`1002` 柜机不存在/软删、`q` 解析不出 `code`）→ 一个**同构的「这个码没用」页**（文案分两种：`1002` 提示可能旧贴纸+联系客服；解析失败提示扫柜机上的码），出口 = 重新扫码 + 回首页看订单。
  - 连带推论：**余位 0 时不得引导「去预约」**——预约同样要 `FREE` 格口（`13.12` 无空闲 → `8002`），唯一真出口是「换一台柜机」。
- **Q8 = (a) 柜机上下文 = 页面参数**（`onLoad` 解析出的 `code` 即全部上下文，不持久化、不跨页共享）；**「不允许隐式记住上次柜机」写成显式约束**（`storage` 存上下文的最坏结果是用户在另一台柜机前被带上上个月的柜机 → 开错柜门）。依据：`13.15 /reservations/:id/use` 按 `reservationId`、取件按 `orderId`，**两者都不需要 `lockerId`**，所以「跨页保住柜机上下文」没有真实用例。
- **Q9 = (b)「我的」页 = 资料 + 积分 + 积分明细入口 + 静态出口（计费说明 / 常见问题 / 联系客服）**，**明确不做「退出登录」**（小程序的登录身份是微信 openid，无法在小程序内切微信账号 → 退出登录唯一效果是把自己踢进一个必须立刻自动重登的状态）。须在 spec 里写「有意不做，不是漏做」。
  - Q9 与 Q5 的耦合：静态内容同时是**降级出口**的内容和**「我的」页**的常驻出口，两条路一份内容。
  - 待复核（不占用户决策）：客服入口载体（`open-type="contact"` 会话 vs 展示电话/微信号）取决于小程序主体与后台客服配置。

### D1 遗留待裁（第 4 轮，仅此一条）
