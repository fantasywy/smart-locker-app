## 要回答什么

把后端**用户端 16 个端点**逐条榨成一张可以照抄的映射表：用户动作 → 端点 → 请求字段 → 响应字段 → 错误码 → 触发时机。范围限 `java/smart-locker/docs/API设计文档.md` v1.0 的 §13（`/api/app/v1/**`）与 §15（错误码），§16（契约增量）作为补充。

## 产出物

1. **逐端点一节**：方法 + 路径、鉴权要求（access / refresh / 无）、请求字段（名、类型、必填性、约束）、响应字段（含可空性）、可能返回的**全部**错误码及触发条件、幂等性说明。
   覆盖：`POST /auth/login`、`POST /auth/refresh`、`POST /auth/logout`、`GET|PUT /profile`、`GET /score-logs`、`GET /lockers/by-code`、`POST /orders`、`GET /orders`、`GET /orders/:id`、`POST /orders/:id/cancel`、`POST /orders/:id/pay`、`POST /reservations`、`GET /reservations`、`POST /reservations/:id/cancel`、`POST /reservations/:id/use`。
2. **四类关键时序各至少一条端到端链路**（列出途经端点与关键字段流转）：
   - 建存件单 → 开门 → 关门 → 取件码生成 → 取件核销
   - 待到支付 → 支付 → 生成取件指令
   - 预约 → 转单（窗口 `[planStartAt − holdMinutes, planStartAt + noShowMinutes)`）
   - 取消（订单 / 预约两条独立路径）
3. **令牌生命周期一节**：access 2h / refresh 30d、`401 + 2005` 的判定与刷新时机 —— 这是 C 端请求层的地基（D1/D7 会引用）。
4. **字段陷阱表**：把容易用错的字段单独列出并注明**禁止**的用法。至少包含：
   - `payable` —— 5 分钟粒度**参考快照**，禁渲染为锁定价
   - `pickupCode` —— 仅「已存入且未取件」时返回
   - `openNotClosed` —— N1，字段名未定，缺失方向安全
5. **空缺点标注**：用户端**没有**站点列表端点，C 端只能按 `code` 反查柜机 —— 这条会直接约束 D1 的入口设计。
