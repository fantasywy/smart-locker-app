**Type**：`wayfinder:task`
**Blocked by**：D3（订单首页如何表达未存入 / 使用中 / 异常）

## 要做的事

建一套 **C 端中文文案体系**，并把「状态 → 文案 → 语义色」三列映射收口成唯一事实源。

背景：admin 侧中文**未集中**（内联在 `orders/index.vue` 等页面），`status-tag.ts` **只有配色、没有文案**；C 端没有可继承的文案表，必须自建，且要与中控屏九态语义对齐。

## 产出物

- `docs/spec/` 下的**文案表**（建议独立文件，供查表使用），最少四列：`后端状态 / 枚举值` → `用户可见文案` → `语义色档位` → `出现位置`。
- 覆盖面：
  - **订单状态**全量（含 `FREE / RESERVED / ... / TIMEOUT / CANCELLED`，以 R1 的表为准）
  - **错误码面向用户的措辞**（`1002 / 3002 / 4004 / 5004 / 6202 / 8001 / 8002 / 8003 / 8006 / 8007` 等 —— 凡 C 端会撞到的）
  - **中控屏九态**在 C 端语境下的对应表述
  - 通用动作词与提示语（按钮、加载、空态、失败重试、二次确认）
- **语气规则**：一段短规则（称呼、标点、不用行业黑话、金额与时间的写法），保证后续新增文案不跑偏。
- 显式标注**禁用词**：例如把内部枚举名或错误码直接展示给用户。

## 约束

- 文案要与 device spec §12 的语义色规则一致：**语义色只做背景/边框/圆点/色条，文字一律走 ink**。
- 不发明后端没有的状态；不确定的字段口径以 R1 / R3 的结论为准。
- **前端不得自造契约**（`smart-locker-admin/docs/adr/0002`）。

## 验收

实现者给任意一个状态或错误码，都能在表里查到唯一文案；新增文案时有规则可依，不必每次重新讨论语气。
