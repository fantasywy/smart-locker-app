**Type**：`wayfinder:task`
**Blocked by**：无 —— 在 frontier 上（**刻意不依赖 D7**，见下方「已知代价」）

## 要做的事

把 device 的视觉语言移植到小程序：**色调层五档 + 语义色只做背景/边框/圆点/色条、文字一律走 ink**。

事实源：`vue/smart-locker-device/.scratch/device-simulator/spec.md` §12（V1–V25）。

## 产出物

- `docs/spec/` 新增「视觉语言」一节：五档色调层的定义、每档的适用语义（正常 / 提示 / 警示 / 危险 / 中性）、以及**使用禁令**（哪些位置禁止用语义色、文字为什么一律走 ink）。
- **SCSS 变量层 + mixin 草案**（这是本 ticket 的技术核心）：小程序**没有 CSS 变量** —— 所以 device 那套 `var(--x)` 做法不能照搬，需要落成 SCSS 变量（编译期）+ mixin（生成具体规则），并给出调用示例。
- 五档 × 典型载体的**对照表**：色条 / 圆点 / 边框 / 背景 各是什么取值，以及**不透明度**如何处理（小程序对 alpha 的支持差异要写明）。
- 与中控屏的对齐说明：哪些取值**刻意一致**（保证同一套语义），哪些**允许不一致**（例如小程序在浅色系统下的可读性取舍）。

## 约束

- 忠实于 §12 的既有裁决，**不得重新发明色调体系**；发现冲突要显式标出，而不是静默覆盖。
- 语义色**只做背景/边框/圆点/色条**，**文字一律走 ink** —— 这条是硬规则。
- 不引入 UI 组件库；不写业务页面。

## 已知代价（刻意保留）
