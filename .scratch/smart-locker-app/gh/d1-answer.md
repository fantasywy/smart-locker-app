## D1 裁决：入口与身份模型

四轮 grilling 收口，**frontier 为空**。11 条裁决 + 3 条派生推论，正文落 `docs/spec/01-entry-and-identity.md`，跨仓库共识落 `docs/adr/0001-c-end-no-locker-browsing.md`。

### 决定性事实（先改掉原票面的一处前提）

`/lockers/by-code` 的「鉴权自相矛盾」**是 R1 的误读**：`§1` 例外清单（`API设计文档.md:25`）紧接 `:24` 的 RESTful 命名说明，是**命名风格例外**（动作型查询用子路径），不是鉴权豁免；`§16 #29`（`:1359`）明写「**需登录态**」，与总则 `:917` 一致。→ **13.6 需要 access。**

由此：未登录时后端不提供任何业务数据（用户端只有 `13.1` / `13.2` 免鉴权），**「未登录扫码看柜机」这条路不存在** ⇒ 登录只能是隐式前置，不能做成用户可见的按需动作。R1 findings 分支已同步更正（commit `e3085c3`）。

### 裁决

1. **扫码两条通道都做**：小程序内 `wx.scanCode`（兜底）+ 微信「扫一扫」直达（体验）。**柜机码载荷统一为 URL** `https://<域名>/l/{lockerCode}`。
2. **三来源收敛**：`q`（`decodeURIComponent` 一次）/ `options.code` / `scanCode.result` → `resolveLockerCode()` → 同一个 `code`；**页面只认 `code`，不关心来源**。
3. **隐式前置登录**：冷启动即 `wx.login` → `13.1`。**一期不设「登录按钮」概念**。
4. **登录失效**：`401+2001` 刷新一次重放；`401+2005` 清态自动重登一次；**同一时刻只允许一次失效处理**（并发 401 约束交给 D7 请求层）。
5. **重放语义**：**完全透明重放（含写请求）**——401 由鉴权拦截器在业务逻辑前返回 ⇒ 请求未执行，重放不构成重复提交；网络超时才是「可能已生效」的分支，靠读接口核对。**重登也失败则丢弃原动作、不做后台补发**（否则会出现「用户离开后自动扣款」）。
6. **资料范围**：昵称头像用「头像昵称填写能力」**自愿填写**，入口**只在「我的」页**；**手机号一期不做**（`phone` 仅首登落库、无换绑端点，会一直撒谎）。
7. **页面骨架**：**两 tab —— 订单 / 我的**。首页 = 订单列表 + 顶部常驻「扫码存件」；柜机页是非 tab 独立页。扫码是动作不是目的地，不做成 tab。
8. **冷启动表现**：骨架屏为常态 + **全局唯一**失败出口（由启动态驱动，不下放到各页数据区）；**不做本地业务数据缓存**（取件码/订单状态属「看到就必须是真的」的数据）。
9. **柜机页异常面**：能拿到数据（含 `online=false`）→ 完整渲染 + **置灰入口并写明原因**（`§16 #29` 明确 `online=false` + 余位 0 是**正常响应**）；拿不到数据（`1002` / 解析失败）→ 同构的「这个码没用」页。**余位 0 不得引导「去预约」**（预约同样只认 `FREE` 格口）。
10. **柜机上下文 = 页面参数**：不持久化、不跨页共享；**禁止隐式记住上次柜机**。
11. **柜机页出口**：顶部固定「我的订单」入口 —— 外部扫一扫直达是冷启动、栈深 1，否则用户「出不去」。

**派生推论**：首登自动注册对用户不可见 ⇒ 不设欢迎页/引导；`scancode_time` 不参与业务；客服入口载体待复核。
