## Answer

**受限态与准入类异常的口径已裁决。** 三轮 grilling 收口（8 + 6 + 4 问，三次均按推荐）。

### 票面前提被修正

**`5004` 只封「开新动作」，不封「收尾动作」。** 票面写的是「拦截下单 / 预约 / 开始使用，但不拦截登录与查看」——准确表述应是**「能看、能做完手上的、不能开新的」**：直接核 `API设计文档.md:1057-1084` 的 `13.11` 规则 1–4，它**只列 `3002/8003/3001/6001`，不含 `5004`**；`13.10` 取消、`13.4/13.8/13.9/13.13/13.14/13.16` 也都不拦。⇒ **受限用户手上已存入的单照样能取出来**。

### 本轮新浮现的两个事实（均逐条对原文行号核实）

1. ⚠️ **C 端拿不到任何一个配置数字。** `score.blacklistThreshold`(60) / `autoRemoveDays`(30) / `timeoutDeduct`(5) / `noShowDeduct`(10) / `reservation.holdMinutes`(15) / `noShowMinutes`(30) 全是可配参数（需求 `:305-316`），而 **C 端 16 个端点里没有任何参数查询**。唯一例外是 `13.7` 响应回显的 `openTimeoutMinutes`。⇒ **「还差 X 分被拉黑」这类预警在诚实前提下做不出来**，本票据此立了一条跨票硬规则。
2. ⚠️ **自动拉黑的 `reason` 服务端原文自带阈值数字**（API `:626`/`:633`「积分低于黑名单阈值（**60**）」），且需求 `:231` 明写自动拉黑**在积分明细留痕** ⇒ 不脱敏会从**两个地方**泄露 60。

### 16 条裁决要点

1. **承载模型**：只在「我的」页常驻 + 动作点就地解释，**不挂全局横幅**（后端意图本就是「能看不能做」，全局横幅会把一个还能正常用的 App 渲染成「你被封了」）。
2. **三个被拦动作一律「保持可见、可点、点击后解释」** —— 不置灰、不隐藏；置灰不给原因只是裸错误码的变体。
3. **`5004` 特判，不走通用 `message` 通道** —— 服务端 message（「黑名单用户禁止该操作」）既不解释原因也不给出路。其余错误码仍按 `message` 直出。
4. **一律事后解释，绝不事前阻断** —— `13.1` 响应就带 `user.status`，但**拦截权只能属于服务端**；本地快照会造出双源真相，会把**已经解禁的用户挡在门外**。也不做本地 `status` 快照（承 `01` §3.2）。
5. **存量单收尾权 = 取件开门 + 取消，两者都保持可用且都不额外解释** —— 详情页取件区块只补一行「账号受限不影响取回本单」。这是本票最有价值的一条，解掉「我的东西拿不出来」这个最大恐慌，且不需要后端做任何事。
6. **归因纪律：只陈述受限、不猜** —— `5004` 遮蔽了 `4004/8002/8003/6201/6202`（`13.15` 的 `5004` 判在 `8003` 之前）。猜错比不猜更糟（用户会去续约、换柜机）。代价照实记：受限用户看到一个**被遮蔽过的世界**。
7. **`reason` 两处共用一套分叉，判据 = `AUTO`/`auto`**：系统生成 → **映射脱敏**（不直出阈值数字）；人工填写 → **直出原文**。定性为**展示层脱敏，不改写历史**。
8. **`auto=false` 的自由文本折叠 3 行 + 可展开**（管理端只校必填，无长度约束）。
9. **申诉 = 说机制不说天数**（`releaseCondition` 不在 C 端契约，管理端 9.4 才有）；自动限制「到期自动解除，以页面状态为准」，人工限制 → 客服。
10. **客服只做 `open-type="contact"` 一个按钮** —— ⚠️ **它是不可运行时探测的**（配置在微信后台，未配时点击静默无反应）⇒ **不做运行时降级、不做电话双出口**（双出口会把一次性配置问题永久固化成 UI）。「后台须配客服」登记为**上线前置项**。**顺带清掉 `01` §5 的「待复核」。**
11. **信用分明细独立成页**：`pageSize=20` + 上拉（终止条件同 `03` §7）；行 = `delta`(正负号显式) + `reason` + `createdAt` + `type`（`AUTO`→「系统」/`MANUAL`→「管理员」）；**`operatorName` 不展示**。
12. **颜色：扣分用警示/危险档** —— ⚠️ **不要套股票口径的红涨绿跌**（这里「分数下降是坏事」）。
13. **规则说明放明细页顶部可折叠段** —— 不新增 `01` §5 的静态出口项（那份清单被 §4 全局失败出口共享，加项会牵动两处）。
14. **硬规则：不得展示任何未经服务端回显的值** —— 判据是「服务端是否在响应里回显过」，**不是**「是不是配置项」（`openTimeoutMinutes` 也是配置项却允许）。`openTimeoutMinutes` 的唯一合法位置 = `03` §8 已定的 P1 建单等待态。
15. **本票兜住 `4004` / `8002`**（与 `5004` 共享同一事务与校验序；经查 `03` §12 与 `01` §7 均未认领）—— 只写失败表现，**不写恢复机制**（「去哪找别的柜机」是入口侧问题，归 `01`）。
16. **不留痕、对称回落** —— 解除后 `status`→`NORMAL`、`blacklistRecord`→`null`，页面回落无限制态，不给「你恢复了吗」的一次性提示（检测状态跃迁需本地快照，与 `01` §3.2 冲突）。被拒动作无副作用，无痕可清。
