# 原型：柜机页「四档格口选择 + 立即存件底部条」

> **PROTOTYPE / throwaway** —— 用来回答 ticket「柜机页：四档格口选择与『立即存件』底部条」的布局与状态问题。
> 不并入 `miniprogram/`，不改业务代码。验证完的 decision 由 map 记录，原型本身留在 `prototype/locker-cell-select` 分支。

## 结论（2026-10-22）

- **布局 A · 2×2 网格**；B 横滑 / C 列表不采用。
- **首屏不预选**：未选中时底部条「请选择格口 / 四档均可存」，CTA 置灰。
- **点「立即存件」→ 二次确认弹层 → 提交中**；失败在底部条内提示。
- **容量只写档名 + 余位**，不写尺寸/示例物品；相对大小只靠图标放大。
- 底部条不出现金额；页面事实行写「具体格口由柜机分配」「费用在取件时结算」。

> 下面的三变体与状态图保留为比较记录；截图里的「中格口已选」只是选中态示意，正式首屏以 `state-nosel` 为准。

## 这个原型回答什么

- 四档卡（小 / 中 / 大 / 特大）用 **2×2 网格 / 横向滑动 / 纵向列表** 哪种布局。
- 选中、售罄、离线、加载中、加载失败、入口失效时，卡片与底部条分别怎么变。
- 底部条左侧显示什么（**不能是金额**），右侧「立即存件」的点击反馈。
- 点击后 **直接下单** 还是 **二次确认**（两种都画了：`state=confirm` 是确认弹层，去掉它就是直接下单）。
- 容量文案的事实边界：后端没有尺寸字段，卡片只写档名与余位，不编「可放 28 寸行李箱」。
- 物理位置：`cellNo` 下单前拿不到，页面不出现「第几行第几列」，只写「具体格口由柜机分配」。

## 怎么打开

```bash
cd docs/prototype/locker-cell-select
python3 -m http.server 8765
# 浏览器打开 http://127.0.0.1:8765/
```

`index.html` 并排展示三个变体；单个页面：

```
phone.html?view=grid|scroll|list
          &state=ready|nosel|soldout|offline|loading|loadfail|submitting|submitfail|confirm|entry
          &selected=small|medium|large|xlarge
          &chrome=0   # 隐藏页面底部的原型切换胶囊（截图时用）
```

- `view` 三个结构不同的变体，底部黑色胶囊或 ← → 键可循环切换。
- `state` 共用同一套数据与状态模型，不写死四份页面。
- 截图（390×844 @2x）在 `shots/`。

## 三个变体

| | A · 2×2 网格 | B · 横向滑动 | C · 纵向列表 |
|---|---|---|---|
| 一屏能看见几档 | 4 / 4 | 1.2 / 4（两侧露边） | 4 / 4 |
| 单卡可用的信息面积 | 中 | 大（大图标 + 容量阶梯） | 小 |
| 选择成本 | 一次扫视 | 需要滑动 1–3 次 | 一次扫视 |
| 主要风险 | 卡片多，单卡信息少 | 四档固定却要藏起三档；容易漏看「特大」 | 像设置列表，转化页的存在感弱 |
| 适合的后续扩展 | 档数固定时最稳 | 将来加档、加图、加推荐语 | 每档要加说明/标签时最稳 |

**A** 是四档固定时的默认假设：四张卡在 390px 宽下刚好两行，不用滑、不用记。  
**B** 把「一档」放大成一张产品卡，容量阶梯（小/中/大/特大）能表达相对大小，但隐藏了另外三档，且滑动本身是成本。  
**C** 最省空间、最容易加第二行说明，但视觉上离「选格口」更远，像设置项。

## 状态提案

| state | 卡片 | 底部条 | 依据 |
|---|---|---|---|
| `loading` | 4 张骨架卡；站点名也是骨架 | 「正在获取柜机信息 / 请稍候」，CTA 置灰 | 首帧结构先出现 |
| `loadfail` | 页内错误块：`加载失败，请重试` + 重试 | 「柜机信息未加载 / 重试后再选择格口」，CTA 置灰 | 失败不是骨架屏；不能复用「这个码没用」 |
| `offline` | 站点 pill 变「离线」；四档全部置灰、写「不可用」 | 「柜机暂不可用 / 可以换一台或稍后再试」，CTA 置灰 | `online=false` 是**正常响应**，页内一行说明，不是弹窗 |
| `soldout` | 四档全部写「已满」，置灰 | 「暂无可存格口 / 可以换一台柜机」，CTA 置灰 | 余位 0 同样是正常响应；不引导「去预约」 |
| `nosel` | 四档正常，未选中任何一档 | 「请选择格口 / 四档均可存」，CTA 置灰 | 显式选择，避免默认档位误导 |
| `submitting` | 保留选中态，卡片整体降透明度、不可再点 | 「正在下单…」+ spinner，CTA 置灰（保留品牌绿，不降对比度） | 技术性防抖 |
| `submitfail` | 恢复可点 | 底部条上方一行 `下单失败，请重试`，CTA 恢复 | 错误贴着动作，不用 toast |
| `entry` | 整页「这个码没用」+ 重新扫码 / 我的订单 | 不渲染底部条 | 沿用既有入口失效页 |
| `confirm` | 正常四档 + 底部弹层「确认存件」 | 弹层盖住底部条 | 二次确认路径的对照 |

> 说明：`state=ready` 的截图为了展示选中态，默认选中「中格口」。真正首屏建议 `nosel`（不预选），见 `state-nosel`。

## 底部条

- 左侧：`已选 中格口` + `余 3 个`。它回答「我选的是哪一档、还剩几个」，不重复金额。
- 右侧：`立即存件`（定稿动作词），48px 高、12px 圆角、`#008655` 填充（白字 4.62）。
- 未选 / 售罄 / 离线 / 加载 / 失败：左侧换成原因，右侧置灰；**置灰必须写原因**。
- 提交中：按钮保留绿色 + spinner，避免降透明度后白字对比度掉到 AA 以下。
- 提交失败：底部条上方一行 `下单失败，请重试`，不弹 toast、不把已选档位清掉。

左侧没有采用两种写法：

1. **只写操作提示**（「选好格口后点立即存件」）——占了一行却不确认任何事；用户点完卡片后最想知道的是「我选的是哪档」。
2. **写金额 / 预估价**——下单前没有金额，API 也不返回；这是硬边界。

## 容量文案

- 卡片只写 **档名 + 余位**（`小格口` / `中格口` / `大格口` / `特大格口`，余位 `3 个可用`）。
- 相对大小只靠两处**非文字**信号：图标随档位放大；B 变体的四格阶梯标注「小 / 中 / 大 / 特大」。
- **不写**「可放 28 寸行李箱」「适合背包」这类断言：后端没有尺寸字段，仓库也没有容量来源，写了就是自编。
- 如果产品坚持要示例物品，需要先定一个**可引用的文案来源**（运营表 / 设备规格），并单独过文案层；本原型不替它编。
- 页面底部一行事实：「具体格口由柜机分配」——对应 `cellNo` 下单前不可得，避免用户以为卡片里的位置就是实际格口。
- 另一行「费用在取件时结算，现在不用付款」——只陈述结算时点，不出现任何金额。

## 本原型不覆盖

- **预约入口**：现有柜机页有「预约」二级入口，本票只做四档选择与底部条，预约在新布局里的落位不在本原型里定。
- **视觉 token 最终值**：圆角 16、卡片阴影、`#008655` 主按钮按 #49 的建议值画；#49 定稿后以它为准。
- **真实接口 / 下单**：数据是静态的；`submitting` / `submitfail` 是按钮态，不调 `13.7`。
- **动效**：只保留骨架屏 shimmer 和 spinner，其余零动效。
