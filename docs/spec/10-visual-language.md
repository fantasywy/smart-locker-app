# 10 视觉语言：色调层与 ink 规则

> 承载 ticket：**T2（#14）**。ADR：**`docs/adr/0002-native-ts-miniprogram.md`**（原生 TS + Sass —— 本文的变量层形态由它决定）。
> 事实源：**device `.scratch/device-simulator/spec.md` §12（V1–V25）** —— 本文**移植**其色调层裁决，**不重新发明**。逐项对齐见 §7。
> 上游：`docs/spec/03-order-list.md` §6（语义档四档）、`docs/spec/09-copy-and-status.md` §1/§2/§5/§7（状态表与文案，本文只引用不重述）、`docs/spec/07-engineering-form.md` §1/§2（工程形态与「小程序没有 CSS 变量」）。
> 本文只写口径与 token 取值，不写业务页面。产物变量层落 `miniprogram/styles/`。

## 0. 一句话结论

**五档色调层（正常 / 提示 / 警示 / 危险 / 中性）只落成 SCSS 变量 + mixin；语义色的原值只做背景、边框、圆点、色条，文字一律走 ink。**

这条硬规则是本文的全部内容。下面每一条都是它的展开。

---

## 1. 前提事实（实现者必须先知道，否则下面的取值看起来像任意选择）

1. **小程序没有 CSS 变量。** device 那套 `var(--x)` **不可照搬** —— 色调层只能落成 **SCSS 变量（编译期）+ mixin（生成具体规则）**（`07` §1 第 1 条，这是本票的技术核心）。编译产物里没有自定义属性，只有展开后的字面值。
2. **语义色都是中明度色，当文字压白底全部过不了 WCAG AA 4.5。** 实测：琥珀 `#e6a23c` **2.19**、红 `#f56c6c` **2.90**、绿 `#00b578` **2.66**、灰 `#909399` **3.08** —— **全部 < 4.5**。**这不是审美偏好，是可读性事故** —— 它正是「文字一律走 ink」这条硬规则的来路，不是一条翻译腔的风格约定。
   - ⚠️ **就地更正 V25 的三个字数**：device spec V25 记作「琥珀 2.06、红 2.57、绿 2.66」。本票用 **WCAG 2.1 标准算法**复算（与 device 自己的 `src/styles/__tests__/tokens.spec.ts` 同一个实现）得 **2.19 / 2.90 / 2.66** —— **只有绿对上了**。琥珀与红的旧值偏低，来源不明。
   - **结论不变**：四个色全部 < AA 4.5，「只能做装饰」这个判断**依然成立**，且本票的 ink 取值（4.77 / 4.53 / 4.62）复算后**逐值吻合**，不受影响。
   - **为什么 device 没发现**：它的单测只断言 `contrast < AA`（`tokens.spec.ts` 的「语义色原值一个不动，且都过不了 AA」），**从不断言具体数值** ⇒ 2.06 与 2.19 都能通过。本票因此把**具体数值**写进验收（§8 第 2/3 条），让这类漂移下次能报出来。
3. **device 的面板是浅色面，小程序也是。** 白底 `#ffffff` 承载全部正文。⇒ device 关于「浅色面」的全部结论**直接适用**，无需为深色模式做第二套变量。
4. **device 的 `$color-scene: #eef2f5`（画布底色）在小程序没有对应物** —— 那是 3D 画布与场景的背景色。小程序的页面底色沿用**后台的** `$color-bg-page: #f5f7fa`（V9 在 device 端把它限定为「面板内部底色」，那条例外随场景一起留在 device）。
5. **五档里订单列表只用四档**，预约列表用**正常 / 危险 / 中性**三档。**「提示」档在现有两张状态表里都没有用户**（见 §4）。它**仍然要出 token** —— 理由是它是色调层的一档，缺一档会让实现者在需要时自造一个琥珀，而自造才是要防的事。
6. **`CONTEXT.md` 与 `09` 已定案的中文文案不在本文范围** —— 本文只管「什么语义用什么色、什么位置禁止用语义色」。

## 2. 五档色调层的定义

| 档 | 变量后缀 | 语义 | 典型使用场景 | 出处 |
|---|---|---|---|---|
| **正常** | `ok` | 在途、无需动作、正向 | 使用中 / 待取件 / 待使用 的状态标签与色条 | `03` §6、`09` §1 |
| **提示** | `info` | 系统信息、非用户责任的中性提示 | **当前无用户**（`09` 两张状态表均未用到）；预留给「传输失败」一类的**中性提示**（device V18 的语义：不是用户输错了什么） | device V18 |
| **警示** | `warn` | 需要你动作，且沉默会有后果 | 待存入 的状态标签与色条 | `03` §6、`09` §1 |
| **危险** | `danger` | 损失在累积 / 用户有责任 | 已超时 / 已爽约 的状态标签与色条 | `03` §6、`09` §1、`09` §2 |
| **中性** | `muted` | 终局、无动作、无情绪 | 已取件 / 已取消 / 已结束 / 已退款 / 已使用 / 已失效 | `03` §6、`09` §1、`09` §2 |

**三条命名纪律**：

1. **档名描述语义，不描述颜色。** 是 `warn` 不是 `amber` —— 改配色时不该改名，改语义时才该改名。
2. **`muted` 不叫 `neutral`/`gray`** —— 它对应 device 的 `$color-info: #909399`（灰），但这个名字表达的是**语义档**（中性），与「灰」这个颜色解耦。
3. **与 `03` §6 / `09` §1 的「语义档」逐字对齐**（正常 / 警示 / 危险 / 中性）—— 那两张表是本文档名的**唯一事实源**，本文只是给它们配上取值。

## 4. 五档 × 典型载体对照表

`x` = 该载体用**原值**；`ink` = 用 §3.2 的 ink；`—` = 该载体在此档不用。

| 档 | 色条 | 圆点 | 边框 | 背景 | 文字 |
|---|---|---|---|---|---|
| **正常** | `#00b578` | `#00b578` | `#00b578` | `#ffffff` | `#008655` |
| **提示** | `#909399` | `#909399` | `#909399` | `#ffffff` | `#646a73` |
| **警示** | `#e6a23c` | `#e6a23c` | `#e6a23c` | `#ffffff` | `#976a27` |
| **危险** | `#f56c6c` | `#f56c6c` | `#f56c6c` | `#ffffff` | `#c05454` |
| **中性** | `#909399` | `#909399` | `#dcdfe6` | `#ffffff` | `#646a73` |

**四条读法**：

1. **左四列永远是原值，右一列永远是 ink。** 这张表就是 §0 那条硬规则的完整展开 —— 没有任何一格例外。
2. ⚠️ **标签底色必须是纯白 `#ffffff`，不是任何「浅灰面」。** 这一条是**实测逼出来的**，不是风格选择（见 §4.1）—— 两个原因叠加：
   - **语义色浅调底会吃掉 ink 的对比度**：红 ink 压红调底最好只有 **4.17**（8%）、绿 ink 压绿调底最好只有 **4.27**，**两档怎么调都过不了 AA**；只有琥珀在恰好 8% 时勉强 4.50（10% 就掉到 4.44）。
   - ⚠️ **连中性浅灰都不够**：页面底色 `#f5f7fa` 压下去，三个 ink 分别掉到 **4.44 / 4.22 / 4.31** —— **全部破线**。它不是「差不多」，是都不过。即便浅到 `#fcfcfd` 仍救不回危险档（**4.42**）。
   - ⇒ **用「纯白底 + 语义色边框 + ink 文字」**：边框给出档位信号（原值做装饰 ✅），白底让 ink 拿回自己的 4.53–4.77。
   - 这一条由验收脚本的第 2b 条守着（§8），**改底色会当场报错**。
3. **「提示」与「中性」在原值上重合（都是灰 `#909399`）** —— 这是**有意的**。两者的差别不在颜色而在**语义**：提示是「系统说了一句话」，中性是「这件事结束了」。**不为区分它们而造第二个灰** —— 那会变成两档灰在界面上互相猜。
4. **中性档的边框用 `$color-border`，不用 `$color-info`** —— 中性档的边框是**卡片的普通边框**，不是「中性色边框」。这是唯一一档这么处理的（另外四档的边框才是语义色）。
5. **文字列一律没有 `#909399`** —— 对照 §3.3：中性文字走 `$color-text-sub`（5.45 ✅），`$color-info`（3.08 ❌）**永不做文字**。

### 4.1 标签底必须纯白：实测表

**这张表是「标签不做色调底、也不用浅灰底」的依据** —— 白面按 alpha 混合后算 WCAG 2.1：

| 候选底 | 琥珀 ink | 红 ink | 绿 ink |
|---|---|---|---|
| **`#ffffff`（✅ 采用）** | **4.77** ✅ | **4.53** ✅ | **4.62** ✅ |
| `#fcfcfd`（浅到几乎白） | 4.65 | **4.42** ❌ | 4.51 |
| `#fbfbfc` | 4.61 | **4.38** ❌ | 4.47 |
| `#fafafa` | 4.57 | **4.34** ❌ | 4.43 |
| `#f5f7fa`（= `$color-bg-page`） | **4.44** ❌ | **4.22** ❌ | **4.31** ❌ |
| 琥珀 8% 调底 | **4.50**（唯一过线） | — | — |
| 琥珀 10% 调底 | **4.44** ❌ | — | — |
| 红 8% 调底 | — | **4.17** ❌ | — |
| 绿 8% 调底 | — | — | **4.27** ❌ |

**三个结论**：

1. **只有纯白同时满足三个 ink。** 任何「浅灰面」的观感收益都不值 0.4 的对比度损失。
2. **降低 alpha 能让对比度回升**（调底越浅越接近白），但即便降到 8%，**红与绿仍然过不了线** —— 那不是「还没调够」，是这条路本身不通。
3. ⇒ **标签 = 纯白底 + 语义色边框 + ink 文字**，这是唯一在**五档全部**成立的形态。

### 4.2 其它需要 alpha 的场合

| 项 | 取值 | 说明 |
|---|---|---|
| 需要半透明（遮罩、浮层） | `rgba()` 函数 | ✅ 唯一允许的 alpha 写法 |
| 8 位 hex（`#e6a23c1a`） | ❌ **不用** | ⚠️ **本票未在本环境实测**，见下 |

> ⚠️ **登记项（未实测）**：8 位 hex 在小程序 WebView 的 WXSS 里是否可用，本票**没有实测**（无法在本环境运行微信客户端）。网络资料互相矛盾（[CSDN](https://blog.csdn.net/u010231454/article/details/131560829) 与 [掘金](https://juejin.cn/post/7252230163730481212) 称可用，[Stack Overflow](https://stackoverflow.com/questions/52930543/8-digit-hex-is-not-a-background-color-value) 记录其在部分环境为草案特性）。**本文因此不给它任何位置** —— `rgba()` 是同等表达力且无争议的写法，没有任何理由去赌。**若实现者实测 8 位 hex 可用，也不得改回**：统一一种写法比省几个字符重要。

## 5. mixin 契约

变量层落 `miniprogram/styles/_variables.scss`，mixin 落 `miniprogram/styles/_mixins.scss`。**四个 mixin，各有明确适用面**：

| mixin | 生成什么 | 什么时候用 |
|---|---|---|
| `tone-bar($tones)` | 左缘 3px 语义色条（`.is-ok` / `.is-warn` / …） | 订单/预约**列表行**左缘、卡片左缘 |
| `tone-chip($tones)` | **标签**：语义色边框 + **纯白底** + ink 文字 | 状态标签 |
| `tone-text($tones)` | **只换文字色**（ink） | 已经是别的载体、只想把文字染成该档 |
| `tone-dot($tones)` | 8px 圆点 | 需要状态点的场合 |

**五条契约**：

1. **`tone-chip` 是唯一同时输出「原值做装饰 + ink 做字」的 mixin** —— 因为标签是唯一一个两种用法叠在一起的地方。实现者**不得**手写标签样式绕过它。
2. **`$tones` 参数必须传「这一处可能出现哪几档」** —— 只排掉用不到的档，免得每个文件里都躺着一份永远匹配不上的规则。**不传 = 五档全出**。
3. **`ink` 只由 mixin 施加，不由调用方选色** —— 调用方给的是**档名**（`warn`），不是颜色。这是「文字一律走 ink」在代码层唯一能强制的地方（`08` 的教训：规则写在文档里，实现者照样会写 `color: $color-warning`）。
4. **档名拼错在编译期报错**（实现里的 `_check-tones`）。没有这条守卫时，把 `warn` 写成 `warning` 会**静默生成一条永不匹配的规则**，而界面照常渲染成中性色 —— 那种错要翻三层才查得到。
5. **禁止在任何 `.scss` 里直接写语义色 hex** —— 一律引变量。这条由 §8 的验收脚本兜底。

## 6. 使用禁令（**硬规则**）

前四条承 device V25 / V9，后五条是小程序特有。

1. **❌ 语义色不得做文字色。** 品牌绿 / 琥珀 / 红 / 灰压白底全部低于 AA 4.5（§1 第 2 条，实测值）。文字一律走 `tone-text` / `tone-chip` 给出的 ink。
2. **❌ 不得整卡、整行、整屏染色。** 语义色**只做背景（标签那种小块）、边框、圆点、色条**。device V18 的原文「错误态一律不整屏染红」直接适用。
3. **❌ 不得给语义色造第二套深色变体。** 每个语义色最多一个 ink，没有 `-dark` / `-light` 的无限色阶竞赛。**绿连 ink 都不新增**（复用 `$color-primary-active`）。
4. **❌ 页面容器不得依赖继承的文字色。** device 曾因继承深色主题的 `#e6e8ec` 导致白底对比度 **1.23**、整片看不见（V9 的「面板文字色」；2026-09-17 用户实际浏览中发现）。小程序没有 `body`、继承链更短，**但同一条规则照写**：页面根节点显式设一次 `$color-text-main`。
5. **❌ 不使用 8 位 hex 表达透明度** —— 一律 `rgba()`（§4.1）。
6. **❌ 不引入 UI 组件库**（承票面约束与 ADR-0002「能不加依赖就不加」）—— 标签、按钮、卡片全部自绘。
7. **❌ 不用语义色表达「可点 / 不可点」。** 承 `04` §3 与 `09` §10：被拦动作**保持可见可点、点击后解释，不置灰** —— 所以**不存在「灰色 = 禁用」这套用法**。中性档是语义档，不是禁用态。
8. **❌ 不把语义色用于「金额大小 / 涨跌」** —— 承 `04` §7.3：**不做股票口径的红涨绿跌**。信用分扣分用**警示/危险档**，是状态语义不是涨跌。
9. **❌ 中控屏九态不对齐** —— device 的九态是**显示态**（屏侧局部态），C 端不感知（`02` §9、`08` §10）。**不得**为对齐屏端再造色档。

## 7. 与中控屏（device）的对齐说明

### 7.1 刻意一致（保证同一套语义）

| 项 | 一致内容 | 理由 |
|---|---|---|
| 语义色原值 | `#00b578` / `#e6a23c` / `#f56c6c` / `#909399` **逐值一致** | 同一套平台语义色，跨端一致才能让运营与客服说同一句话 |
| 两个 ink | `#976a27` / `#c05454` **逐值一致** | V25 的审计结论与端无关；且它们的对比度是按**白底**算的，小程序同样是白底 ⇒ 结论直接可搬 |
| 绿色文字 ink | `#008655`（复用 `$color-primary-active`）**逐值一致** | 同上 |
| 中性文字三档 | `#1f2329` / `#646a73` / `#8f959e` **逐值一致** | 三档的**语义分工**（承载信息 vs 占位符）比取值本身更重要 |
| 面与边框 | `#ffffff` / `#f5f7fa` / `#dcdfe6` **逐值一致** | — |
| 圆角两档 | `4px` / `8px` **逐值一致** | — |
| 色条宽度 | `3px` **逐值一致** | `03` §5 的「左缘 3px 语义色条」直接承 V24 |
| 间距六档 | `4/8/12/16/20/24` **逐值一致** | — |
| **核心硬规则** | **语义色只做装饰、文字一律走 ink** | 本文的全部内容就是移植这一条 |

### 7.2 允许不一致（且**不是**疏忽）

| 项 | device | 小程序 | 为什么允许不同 |
|---|---|---|---|
| **字体栈** | 含 `'Segoe UI'`（桌面） | **去掉 `'Segoe UI'`** | 它是 Windows 桌面字体，在小程序（iOS/Android WebView）上永远匹配不到。**留着不是错，只是死字符串** —— 这里删掉，不标为偏离 |
| **`$color-scene: #eef2f5`** | 3D 画布底色 | **不存在** | 小程序没有 3D 场景。页面底色用 `$color-bg-page` |
| **标签背景做法** | 面板里多用「白底 + 灰边框」的 chip（V24） | **纯白底 + 语义色边框** | 小程序的状态标签是**列表行里最小的信息单元**（`03` §5），需要比调试面板的筛选 chip 更强的可辨识度。⚠️ **底在两端都是白的**，小程序只是把边框从灰换成语义色（§4.1 实测：浅灰面会把 ink 压破 AA） |
| **`$z-*` 四层** | 有（画布 / 中控屏 / 面板 / 浮层） | **不移植** | 那是 3D 场景的叠放秩序。小程序用原生导航栈，z-index 只需处理「自定义导航栏 / 内容 / 浮层」三处，按需在页面内声明即可 —— 预造一套四层 token 是给不存在的需求立法 |
| **`$font-size-panel-title: 18px`** | 面板标题 | **不移植** | 那是 380px 面板的几何产物。小程序改用 `$font-size-title: 16px` + `$font-size-display: 28px`（取件码要「大号、常驻」，`08` §5） |
| **组件密度** | 380px 面板、11px 大量使用 | **正文以 14px 为主，11px 仅副行** | 小程序是手指操作的移动端，可点目标与字号下限都更严 |
| **单位** | `px`（桌面定点） | **`rpx` 用于需要随屏宽缩放的几何** | 见下 |

> **单位（小程序特有）**：device 是桌面定点（1440×900 验收），用 `px`。小程序需在**不同屏宽**下保持版式，因此**布局几何用 `rpx`**（`750rpx` = 屏宽），**字号与 1px 级细节（色条 3px、边框 1px）用 `px`**。
> 依据：`03` §5 的「左缘 3px 语义色条」在 device 是物理 px；小程序若写成 `3rpx`，在 375pt 屏上只有 1.5px，**低于可辨识下限**。**色条宽度刻意保持 `px`** —— 它是文档级一致（§7.1）而非缩放项。
> ⚠️ 这条是**本票的工程裁决**（device 无对应物），不是 V1–V25 的移植。

### 7.3 对照结论一句话

**色值层 100% 一致，几何与运行时有 6 处有意的偏离 —— 全部是「桌面 Web ≠ 小程序」的产物，没有一处是色调体系的重新发明。**

## 9. 本票定的版式（T1 `#14` 交接项）
`09` §11 只留了**一项择一**给本票：

> 「参考金额」的两种合法形态**择一**（标签行 + 金额行 / 单行合写 `参考 ¥12.00`）

**裁决定版：标签行 + 金额行。**

```
参考金额
¥12.00
```

**理由（三条，其中第一条是决定性的）**：

1. ⚠️ **这一项其实已经被上游定过，本票只是止住一处跨 spec 分叉。** `06` §3.2 的原文裁决是「进页面就显示参考金额；**金额单独一行** + 「参考」二字；按钮不承载金额」—— **「单独一行」就是「标签行 + 金额行」**。而 `09` §5.3 后来把它写成「两种都合法，由 T2 定版式」。⇒ 两处**不矛盾但也不一致**：`06` 已经倾向了形态一，`09` 把它重新打开了。本票按**更早、更具体**的 `06` §3.2 收口，并**就地补正 `09` §5.3**（见 §10）。
2. **金额行可以独立排版。** 它要按 `09` §5.3 的规则渲染（`¥` 紧贴、两位小数恒显、不分组、不换行），单独一行让金额本身获得视觉重量 —— 而合写形态里「参考」二字和数字抢同一行的宽度。
3. **`TIMEOUT` 单上金额还在涨**（`06` §5.3）。独立金额行在数字位数变化（`¥9.00` → `¥100.00`）时**不动标签行**，合写形态会让整行重排。

**这一条同时冻结 `09` §7.8、`:550` 的「也可合写」分支** —— 全端只有一个形态。

## 12. 刻意不做（避免被当成漏做）

- **不做深色模式 / 主题切换** —— device V1 明确废弃深色基调、V9「不保留第二套深色变量」；小程序同样只出一套浅色。
- **不做 CSS 变量（自定义属性）** —— 小程序没有（`07` §1）。
- **不造 `-dark-1…5` 色阶** —— 每档最多一个 ink（§6 禁令 3）。
- **不把色调层做成组件**（如 `<tone-tag>`）—— 本票只出变量与 mixin；组件在 `07` §3 的 `components/` 里按需建，本票不预造。
- **不为「禁用态」造色** —— 见 §6 禁令 7：被拦动作不置灰。
- **不移植 `$z-*` 四层、`$color-scene`、`$font-size-panel-title`、面板几何** —— §7.2 逐项已说明。
- **不写业务页面样式** —— 本文与产物都只到「token + mixin + 用法」为止。
